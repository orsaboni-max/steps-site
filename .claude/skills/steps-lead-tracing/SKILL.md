# STEPS — זרימת אבחון ליד 🔎

מתי: אור שואל "איפה הליד / לא ראיתי אותו / מאיזו מודעה / למה בלי טלפון / מה הסטטוס".
מטרה: לענות עם **נתון חי**, בלי לנחש, בלי לשאול את אור לחפש בעצמו.

## שלב 1 — מאיזו מודעה הגיע הליד? (Meta MCP)
שואלים ברמת **ad** (לא רק campaign) כדי לדעת מי באמת מביא לידים:

```
ads_get_ad_entities(
  ad_account_id="9773300439396945",   # ILS, חשבון STEPS הפעיל
  level="ad",
  fields=["id","name","amount_spent","impressions","clicks","ctr","results","cost_per_result","lead","effective_status"],
  date_preset="last_7d",
  filtering=[{"field":"campaign.id","operator":"EQUAL","value":["<campaign_id>"]}]
)
```

- `lead` = מספר הלידים פר-מודעה. `results` עם `actions:leadgen.other` = אותו דבר.
- **שדות חוקיים ברמת campaign/adset/ad:** `amount_spent` (לא `spend`), `results`, `cost_per_result`, `lead`, `ctr`, `cpc`, `impressions`, `clicks`, `effective_status`. **`actions`/`spend` לא קיימים** → שגיאת VALIDATION.
- 🔴 **ממצא נעול (11/6/26): בקמפיין KIDS — הסטורי 9:16 ממיר, הקרוסלה = 0 לידים.** הקרוסלה הוציאה ₪92 → 0; הסטורי ₪46 → 1. אם מגדילים תקציב — לסטורי, לא לקרוסלה.

## שלב 2 — איתור הליד ב-Arbox (⚠️ ה-API מטעה!)
**אל תשתמש ב-Arbox MCP / arbox_raw_get כדי לאתר ליד ספציפי לפי תאריך/מקור.**
ה-API מחזיר את **כל** הלידים (~4314) **ממוין אלפביתית**, קוטם ל-20 הראשונים, **ומתעלם** מ-`source_id`/`orderColumn`/`limit`. תקבל תמיד את אותם 20 לידים שמתחילים ב-`_`,`.`,`$`.

✅ **הדרך הנכונה — `trace_lead.py`** (ב-`C:\Users\USER\steps-brain`, משתמש ב-ArboxClient של הבוט שטוען את המפתח מ-.env מקומי, מסנן locally, מדפיס רק שם/טלפון/תאריך — לא חושף סוד):

```powershell
Set-Location C:\Users\USER\steps-brain
python scripts/trace_lead.py "הרפז"             # לפי שם
python scripts/trace_lead.py --source 99396      # מקור "אימוני ילדים" (=הפַּס שלנו, נבדל מהסוכנות)
python scripts/trace_lead.py --phone 0525177739  # לפי טלפון (9 ספרות אחרונות)
python scripts/trace_lead.py --recent 10         # 10 הלידים האחרונים
```

- מקור **99396 = "אימוני ילדים"** = הפַּס הייעודי שלנו. מקור **"Facebook" (1127)** = הגנרי של הסוכנות.
- `leads_summary` של ה-MCP **כן** טוב לאגרגציה (כמה לידים פר-מקור + המרה), רק לא לשליפת רשומה בודדת.

## שלב 3 — ליד בלי טלפון? = לקוחה חוזרת (לא תקלת מיפוי!)
🔴 **המקרה הנעול (11/6/26):** ליד "איה הרפז" נכנס עם **טלפון ריק**. זה **לא** באג ב-Zapier.
בכרטיס Arbox קפצה משימה מסוג **`exisitingClientWasAdded`**:
> "המשימה קפצה בגלל שמשתמש **שכבר קיים** במערכת שלכם, השאיר פרטים בדף הנחיתה. לצפיה בפרופיל: .../user-profile/**2037570**"

**ההסבר:** כשמתעניינת **שכבר קיימת** ב-Arbox ממלאת טופס מודעה, Arbox מזהה אותה (לפי טלפון/מייל), יוצר **רשומה כפולה ריקה** (בלי טלפון) + מקפיץ משימה שמפנה ל**פרופיל המקורי**. **הטלפון יושב בפרופיל המקורי, לא ברשומה הריקה.**

- **פעולה:** לפתוח את הלינק שבמשימה (`user-profile/<id>`) → שם הטלפון. (אי-אפשר דרך API — `/user/{id}` מחזיר `Not allowed`; `get_users` מחזיר רק ~692 מסונן; הפרופיל לא בהכרח ב-leads/memberships.)
- **מסקנה חיובית:** הפַּס תקין (טופס→Arbox עובד). זו פשוט מתעניינת חוזרת — עדיין שווה לחייג.

## שלב 4 — "למה לא ראיתי התראה?" (לוג הבוט)
הבוט `steps-brain-bot` שולח התראת טלגרם על כל ליד חדש (`check_new_leads`, כל 2 דק').

```powershell
$job = Start-Job { Set-Location C:\Users\USER\steps-brain; railway logs --service steps-brain-bot }
Start-Sleep -Seconds 18; Stop-Job $job; (Receive-Job $job | Out-String) -split "`n" | Select-Object -Last 70; Remove-Job $job -Force
```

- ⚠️ ה-CLI מקושר ל-service **steps-brain** (הכפיל המת) — **תמיד `--service steps-brain-bot`** מפורש.
- ⚠️ `Start-Job` חייב `Set-Location C:\Users\USER\steps-brain` בתוך ה-scriptblock, אחרת "Service not found" (מאבד את ה-link).
- ⚠️ `railway logs` מציג רק **זרם חי** (הדקות האחרונות) — לא היסטוריה. ליד מאתמול לא יופיע. אם צריך לאשר התראה היסטורית → לבדוק את ה-watermark/state בקוד, לא בלוג.
- 🚫 **לא להדפיס משתני-סביבה/סודות מ-Railway** (`railway variables`) — הקלסיפייר חוסם, ובצדק. להשתמש בסקריפט שטוען מפתח לבד.

## צ'ק-ליסט תשובה לאור (סדר)
1. מאיזו מודעה → שלב 1 (Meta, רמת ad).
2. הליד עצמו (שם/טלפון/סטטוס) → שלב 2 (`trace_lead.py`).
3. טלפון ריק? → שלב 3 (לקוחה חוזרת → לינק לפרופיל מקורי).
4. לא קיבל התראה? → שלב 4 (לוג הבוט) — אבל לרוב לא קריטי.
5. תמיד לסיים ב**מסקנה תפעולית** (לחייג / סטורי-מנצח / הקרוסלה לא ממירה), לא רק נתון.
