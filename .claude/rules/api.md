# כללי `api/` (Vercel API Routes)

## `api/lead.ts` — טופס הלידים → Arbox
- `source_id 19357` = מקור **`Website`** ב-Arbox. הסימן היחיד והוודאי שליד הגיע מהטופס — לא לשנות. ("אתר " עם רווח = מקור ידני של המזכירות, לא שלנו.)
- הגבלת קצב: 5 פניות ל-10 דקות לכתובת (`MAX_PER_WINDOW`). מונעת הצפת CRM — לא להסיר ולא להרחיב בלי כשל מוכח.
- ההערה על הליד מתחילה ב"הושאר בטופס באתר…" ומוסיפה מקור-הגעה (עד 300 תווים, `REF_MAX`).
- honeypot → תשובת הצלחה מזויפת בלי ליד ובלי אירוע מדידה.
- שגיאות Arbox לא דולפות ללקוחה — הודעה גנרית בלבד. הטופס נשאר ניתן לשליחה חוזרת.

## `api/schedule.ts` — מערכת השעות
- `date` חייב לעבור `^\d{4}-\d{2}-\d{2}$`, אחרת ברירת מחדל היום. בלי הולידציה ניתן להזריק `to_date` ולמשוך טווח שרירותי (אומת חי 2/8/26: 132 פריטים במקום 21).
- מפתח: `process.env.ARBOX_API_KEY` בכותרת `api-key`. חסר → שגיאה גנרית, לא דליפה.
- סינון: רק `location_name` שמכיל "פולג". קריית השרון נמכר — אסור להציג.
- `Cache-Control: public, max-age=300`.
- Arbox מחזיר רק `max_participants` — אין נתון תפוסה, ולכן אין "מקומות פנויים" בשום מקום.
